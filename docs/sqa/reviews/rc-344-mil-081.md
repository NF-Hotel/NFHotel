## Findings

- **Finding 2 is in the upstream configuration, not in a guess.** Line `http-request allow if { path,url_dec -m reg -i ^(/v[\d\.]+)?/containers } { env(CONTAINERS) -m bool }` of `haproxy.cfg` v0.5.0 has no end anchor and no list of sub-paths, and the first rule refuses only methods other than `GET` and `HEAD` while `POST` is `0`. So every `GET` under `/containers` passes. The Docker Engine API serves the files of a container by `GET /containers/{id}/archive` and its filesystem by `GET /containers/{id}/export`, and `GET /containers/{id}/attach/ws` opens a WebSocket.
- **The repository is public, and the finding is not an open door.** Only Alloy reaches the proxy, over an internal network, so a use of finding 2 needs a takeover of Alloy first. The plan describes what the proxy lets through, as the upstream documentation does, and no way into Alloy; the fix is deployed within the run.
- **Criterion 3 shows that the test sees the finding**, so the matrix is not written to pass.
