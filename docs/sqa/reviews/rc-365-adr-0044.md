## Findings

- **F1, a stand-in decision open to S01: no approval of its own.** A release on the VM waits for the approval of S01
  in the environment `production` ([ADR-0038]); a deploy of the monitoring does not. The gate is the pull request
  with its required checks, which S01 merges or lets the AI merge under the plan, and the Ops CI run of the merge.
  S01 asked on 2026-11-01 for a change that reaches the monitoring without a manual step, so the reviewer accepts
  it, and the ADR now names it among the negative consequences. If S01 wants an approval here too, a workflow job in
  an environment that S01 approves can mark the commit, and the pull can read that job from the API as it reads the
  Ops CI run, with no new access to the LXC.
- **F2, fixed in the review: a change made by hand.** `git checkout` carries a change of a tracked file over to the
  head when the head does not change that file, so the stack would start a configuration that no review saw, for
  example the threshold of the alarm drill of the wiki page Monitoring. Decision 4 now refuses such a checkout at the
  stage `checkout` and keeps the change (6db511c); the pull test proves the refusal and the deploy after the change
  is undone.
- **F3, fixed in the review.** The missing approval is in the consequences (3d5e10c), and CI is spelled out at its
  first use. Decisions 7 and 8 said that the report and `MonitoringDeployStale` follow the last run that ended
  well; the pull writes the report at every run that read `main`, also one that refuses a commit, so they now say
  that, as the alert and the wiki do.
- **F4, note: the limit of the API.** Without a token, GitHub allows 60 calls an hour from the address of the LXC.
  The pull asks only while a change of the monitoring paths waits for its Ops CI run: at most 30 calls an hour, and
  about 3 for a merge whose run takes 5 minutes. A failed call fails the run, which writes no report, so
  `MonitoringDeployStale` fires when it lasts an hour. The scan exporter reads the API with its own token.
- **F5, note: the trust of the timer.** The pull runs the scripts of the fetched commit as root, as the manual deploy
  does and as `nfhotel-deploy update` does on the VM ([ADR-0018] through CD); decision 3 limits it to a commit of
  `main` that descends from the deployed one and whose Ops CI run passed.
- **[ADR-0020] needs no change.** It says where the monitoring runs and what it collects, not how a change reaches
  the LXC, so it states nothing that the pull makes false.

## Overall Verdict

autonomous mode, under the plan that S01 accepted in chat on 2026-11-14; F1 stays open to S01's challenge.
