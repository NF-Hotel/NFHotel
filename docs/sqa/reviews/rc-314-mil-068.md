## Findings

- **The survey found a trap that the CIS checklist does not name.** Row 2.1.x of CIS-001 proposes to purge the desktop tasks. The simulation with `--auto-remove` would purge 12 packages, `sudo` among them, and leave GNOME installed. The deploy account runs `nfhotel-deploy` through `sudo` (`install-deploy-user.sh`: the user `deploy` and the rule for `/usr/local/sbin/nfhotel-deploy`), so the next CD run would fail. The plan answers with the packages to keep marked as installed by hand before the purge, the case that refuses written first (task 2), and `sudo -l -U deploy` in criterion 4.
- **NetworkManager stays.** It manages `ens18`, and `/etc/network/interfaces` holds only the loopback, so removing it with the desktop would take the VM off the local network and the tailnet. The plan keeps it rather than move the network in the same change.
- **Row 2.2.x was added before this record.** Row 2.2.x of CIS-001 says that `inetutils-telnet` came with the desktop install and goes with it. The plan named only row 2.1.x; the removal list, criteria 3 and 5, the dependencies, the traceability and task 3 now name both rows.
- **The plan matches the code of `main` at e2dadb6.** `install-deploy-user.sh` sets `DEPLOY_USER=deploy` and `COMMAND_PATH=/usr/local/sbin/nfhotel-deploy`; `ops/deploy/systemd` has `nfhotel-backup.service` and `nfhotel-firewall.service`; the survey listed `cupsd` (port 631 on the loopback) and `avahi-daemon` (port 5353 on every address) beside `sshd`, `tailscaled` and the ports of Docker, so criterion 3 names what must be gone.
- **The change on the VM needs S01.** Task 5 starts only after S01 has taken a Proxmox snapshot and named a time for the outage; when a check fails, S01 rolls back to the snapshot from the Proxmox console.
- **An abbreviation and a trace were changed before this record.** AI is spelled out in task 5 (criterion 10), and the traceability row names objective 25 beside success criterion 28 (criterion 4).
- **The acceptance covers the language and the terms.** As for MIL-067 ([RC-309]), criteria 3, 5 and 9 rest on the acceptance of S01, who can challenge them in the summary of the run.
