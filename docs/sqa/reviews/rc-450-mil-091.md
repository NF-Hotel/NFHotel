## Findings

- **The cause in finding 2 is a reading, not a proof.** The logs of the backend of Docker Desktop that are left have no line about port 2222 from 21 to 24 November, so the plan says "most likely". The drill of criterion 3 shows what a start without the tailnet address does to the service. If the service then stops instead of running without its port, `docker compose up -d` already starts it again, and the check of the port still covers the case that was seen.
- **The new check of Ops CI is not required at first.** A new entry of the script tests makes a new check. It blocks a merge only after S01 adds it to the rules of the branch, because the settings of GitHub are S01's; task 1 says so.
- **The drill depends on S01.** It needs Tailscale down and up on the backup host, which only S01 does. Without the drill, criterion 3 cannot pass. S01 kept it when accepting the plan.
- **What the plan makes public.** The plan names the times when the backup host slept and started from 21 to 24 November, port 2222 and the six days without a copy. It names no address, no device of the tailnet and no credential. [MIL-074] published the same kind of facts, and the repository is public.
- **Mode.** Supervised: S01 accepted the plan on 2026-11-27, and nothing is committed, published or built before S01 asks for it.
