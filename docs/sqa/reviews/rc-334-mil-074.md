## Findings

- **What the hourly copy can and cannot do.** It takes the limit of 72 hours from "two nights" to "the backup host on at least once in 72 hours". A host that is off for longer still raises `OffVmCopyStale`; only a second target that is always on would change that, which is a decision of S01 on D7 and the costs.
- **A down target is told from an off host by Tailscale.** `tailscale ping` reaches the host when it is on the tailnet, whatever runs on it, so `BackupTargetDown` fires only when the host is on and the copies fail, and a weekend with the host off raises nothing new.
- **The two runs cannot collide.** The lock makes the hourly copy skip while the daily backup runs, and the copy never sends a part of a dump, because the backup writes `*.partial` first and the copy takes only the final names.
- **The scheduled task changes S01's computer.** Task 4 is done only on S01's yes in chat, and the restart of Docker Desktop for criterion 5 needs its own yes.
- **Tonight is not covered by this plan.** The copy of 2026-11-12 runs inside the nightly backup at 02:00 to 02:10 UTC, near the limit of 72 hours after the copy of 2026-11-09; the AI's request to start it earlier on the VM was refused by its safety check, so S01 was told how to start it.
- **Not independent.** The AI that walked the checklists wrote the plan; the acceptance is S01's decision.
