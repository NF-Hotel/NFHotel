## Findings

- **A wait on the required port only.** The other ports must not answer, so a wait on them would only make the step slower; they keep the single five-second try, after port 22 has answered and so proven that the path is up.
- **The proof is the next deploy.** Criterion 3 cannot be tested in Ops CI, because the race lives between a fresh tailnet node and the VM; the CD run of the merge is the first run with the wait, and its log line is the evidence. A later run that fails the step after a full minute is a real finding, not the race.
- **Sixty seconds is a ceiling, not a delay.** The step returns as soon as the port answers; on 2026-11-05 the second attempt answered at once, and the first would have answered within seconds.

## Overall Verdict

Go. Every Mandatory criterion passes. The plan is one function with a default, a test for each side of it, one wiki row and a proof that the next deploy gives. The reviewer is not independent.
