## Findings

- **The fix keeps `sudo`.** `runuser` or `setpriv` would remove the log line along with the secret, so the change of user would leave no trace; a temporary file would put the secret on disk once more; no log for root would end the audit trail of MIL-023 (rows 5.2.1 to 5.2.3 of CIS-001). Standard input moves only the value: `sudo` still resets the environment and logs the command, which holds no secret. ADR-0041 records the choice (task 1).
- **The order is the point of the plan.** The fix is deployed before the new password: a deploy with a new password and the old `as_app` would write the new password into the same logs. The deploy that waits for S01 now (CD run 42521794478, 4d67484) writes the same, already exposed password again and adds no new reader.
- **The plan matches the code of `main` at 4d67484.** `as_app` (`ops/scripts/deploy-release.sh`, lines 128 to 137) passes `NFHOTEL_API_CONNECTION_STRING` with `--preserve-env`; `api_database_settings` reads it from `/etc/nfhotel/secrets/nfhotel-api-database.env`; `prepare-database-roles.sh` makes a password file only when it is missing, so moving `postgres-app.password` aside makes a new one at the next `--apply`; `write-secret-files.sh` builds the secret file of the API from the variable; the log of `sudo` goes to its own file (`ops/deploy/host/sudo/nfhotel-logging`); the journal is persistent with at most 1 GB (`ops/deploy/host/journald/nfhotel.conf`); Loki keeps 14 days (`ops/deploy/monitoring/loki/config.yml`); Alloy reads the whole journal with no stage that drops a field (`ops/deploy/alloy/config.alloy`).
- **The counts were taken without printing a line.** Only counts and times: 186 entries in the journal from 2026-10-21 06:12 to 2026-11-08 20:26 UTC, and 7, 50 and 43 in `sudo.log` and its two older files. The job log of the cancelled run on GitHub holds no `Password=` field.
- **The new password needs S01.** Task 5 starts at a time S01 names, after task 4; between the change of the role and the next deploy the API cannot open a new connection, so S01 approves the new CD run right away.
- **Abbreviations were spelled out before this record.** API in the Purpose, SSH in task 5 and CI in the deliverable (criterion 10).
- **The acceptance covers the language and the terms.** As for MIL-068 ([RC-314]), criteria 3, 5 and 9 rest on the acceptance of S01, who can challenge them in the summary of the run.
