## Findings

- **F1, fixed: HTTP status codes.** "(403)" in 1a, "(401)" and "(429)" in 5a and "(404)" in 9a are implementation detail (criterion 12). Removed; each reason stays in words.
- **F2, fixed: extension 5b.** It said that the system "says that it was not recorded". The page shows the text of the failure instead, for example "We couldn't reach the hotel system. Please try again in a moment." (test `StartAsync_RecordFails_FollowsTheRunAndShowsTheText`). Fixed: "shows why the hotel system did not record it".
- **F3, fixed: rule 8.** When Ollama does not answer at the deployment, `apply_default_model` writes the name of the default without the check, with a warning; the rule said only that a default that is not installed is not written, and [ADR-0014] does not name the case. Added: "when the model server does not answer at the deployment, the name is written unchecked".
- **F4, fixed: extension 2d.** It took "the last recorded run" and gave one reaction to two cases. The page shows the newest run of the last seven days that failed or was interrupted when no run is followed, also when a later run finished; a start again from the list of runs takes the choice at once, without that notice. Split into 2d and 2e, as the code does them. The notice is headed "The last run did not finish" also when a later run finished; that wording is the page's and is noted here, not changed.
- **F5, finding: the paused note of the panel of the installed models.** [MIL-020] criterion 12 and task 11 ask the Start page and the panel of the installed models to say that the live view is paused when a read fails. The page does it for the runs and the models (`BenchmarkStartViewModel.IsLive`). The panel sets `BenchmarkModelsViewModel.IsLive` when the read of the downloads fails, but `ModelsPanel` never shows it. The use case states what the code does (6c and open issue 3); the change of the code is S01's (action item).
- **F6, fixed: open issue 1.** It said that UCD-001 names DevOps as the actor; since [RC-368], UCD-001 names DevOps, who runs the service, and Hotel staff (Manager), who starts a run. Reworded; whether US-001.04 and the goal Choose Local AI Model change is S01's decision (action item).
- **F7, note: more than one goal.** Steps 8 to 10 (the default AI model, the delete of a stored run, the delete of a model) are goals of their own. They are here because [MIL-020] built them on the Start page and the list of runs, and [UCD-001] has no use case for them besides Choose Local AI Model, which open issue 1 names. Kept.
- **F8, note: the benchmark service was not read.** Its queue, the checks it makes again, one model at a time and its refusal to delete a model in use rest on the codes and texts of `BenchmarkServiceClient` and `ErrorMessages` and on [MIL-020]; the code of `notebook-benchmark` is not in this repository.
