## Findings

- **The deploy contract changes, not the call.** The references that CD passes carry their names, so the call of `nfhotel-deploy deploy` keeps its shape; what changes is how the command checks, applies and logs them. The riskiest path is the rollback from the first release with five images to a release line with four, so MIL-064 criterion 5 asks for a test of exactly that.
- **The layer leaves nginx itself.** The upstream nginx comes from nginx.org, and the Alpine 3.23 repository has an older nginx, so `apk upgrade` does not replace it today. Decision 1 adds a check of the nginx version to task 2, so a later base where Alpine has the newer nginx cannot swap the build without the release noticing.
- **One more image can stop every release.** A fixable finding that the layer cannot reach, such as one in nginx itself, now fails the release gate for all five images until the upstream image brings the fix or the finding is accepted for 30 days. ADR-0030 accepted the same coupling for market-analysis; the record names it among the negatives.
- **The rule is applied later.** Decision 5 gives each failing third-party image one of three remedies; MIL-064 task 9 applies it from the first full daily scan, so this record does not yet say which image gets which.

## Overall Verdict

Go. Every Mandatory criterion passes. The record chooses the option that removes the known fixable findings through the path the release already has for its own images, and changes the deploy command once so that the next patched image does not change it again. The verdict is S01's; the checklist was walked by the AI that wrote the record, so the review is not independent of the author.
