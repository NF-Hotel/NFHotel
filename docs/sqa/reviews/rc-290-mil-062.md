## Findings

- **Two releases, not a time window.** The one-line command given to S01 keeps images younger than 24 hours; the plan keeps the images of the two latest releases of the log whatever their age, because the rollback command goes to the release before the latest one and a quiet week must not make that rollback a new pull. The images a third-party release of the previous deploy pinned (nginx, cloudflared, Alloy) are kept only while a container uses them; a rollback that needs an older one pulls it again, which the deploy can do.
- **The first run is the cleanup.** The CD run of the merge installs the new command before it deploys (ADR-0018), so the 348 images of 2026-11-05 go at the end of that deploy, whether or not S01 ran the one-line command first.
- **A warning, not a failure.** A deploy that passed its smoke test stays green when an image cannot be removed; criterion 3 makes that a tested behaviour, so housekeeping can never roll back a good release.

## Overall Verdict

Go. Every Mandatory criterion passes. The plan is small, the rule is one sentence with its reason, and every criterion has evidence that a test, a command on the VM or the monitoring gives. The reviewer is not independent.
