## Findings

- **The finding was tested, not assumed.** The plan rests on the code on `main` (1c2726b) and on two pages of the live
  site, opened without signing in on 2026-11-12. The page showed dates, nights, room type, status and payment text for
  `FLZ-000001`; the team had kept name, email, phone and passport number off the page (BR-C-06), so no personal data
  was shown.
- **The evidence of the open read is kept before anything changes.** At S01's request ("husk at inkludere screenshots
  og andet bevis") the AI saved on 2026-11-12 at 10:47Z two screenshots of the live receipt page, made with headless
  Chrome and its own throwaway profile, so without the address bar: `FLZ-000001` with its card and the line "Keep this
  number. It is the key to this page.", and `FLZ-999999` with the not-found text. It also saved three transcripts, with
  the public address in a variable: the read by id without `RequiresPermission` beside the overview with it; the fields
  of `FLZ-000001`; and a count of four numbers (`FLZ-000001` to `FLZ-000003` shown, `FLZ-999999` not found). None holds
  personal data. Task 4 puts them in `docs/sqa/evidence/mil-079/`.
- **The API is not open to the internet.** Every `/api` path needs the API token of the web application, apart from
  the sign-in and the room endpoints of the mobile app; the open read is reached through the receipt page. The plan
  still closes the API, because the page is a convenience and the API the authority (MIL-018 decision 5).
- **The size is the read only.** The guest sign-in, the guest token, the cookie and the change pages of MIL-018 stay
  there. Changes and cancellations already need `Bookings.EditOthers`, so the read is the open part.
- **Not independent.** The AI that walked the checklists wrote the plan; the acceptance is S01's decision.
