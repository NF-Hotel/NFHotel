## Findings

- **Two answers of the designer are read, not quoted as decisions of the plan.** The designer answered the open points of the wiki page in chat through S01 on 2026-11-05: "Det er et levn der ikke skal med" (a leftover that does not go in) and "Spørgsmålet forstår jeg ikke" (I do not understand the question). The plan reads the first as the notebook route, which is dropped with the listener, and the second as the Ollama question, which `market-analysis.env.example` settles (`ollama:11434`). Both readings are in the Purpose, so that S01 or the designer can correct them before task 4 deletes the template.
- **The network is internal.** The plan makes `nfhotel-python` an internal network like `nfhotel-api` and `nfhotel-db`. The two Python services keep their route out through `nfhotel-llm`, which is an ordinary bridge so that Ollama can download models; nothing on `nfhotel-python` needs a route out. If a later service on that network needs one, the ADR records the choice to reconsider.
- **The deploy needs no change on the VM.** Every compose file names the new network with a default (`${NFHOTEL_PYTHON_NETWORK:-nfhotel-python}`), and `deploy-services.sh` creates it, so the git-ignored environment files on `nf-hotel` are not touched by the move; the lines they keep for the old listener become unused. Removing them is housekeeping for S01, not a criterion.

## Overall Verdict

Go. Every Mandatory criterion passes. The plan is small, each task names its files, and every criterion has evidence that a test, a command on the VM or a record gives. The reviewer is not independent.
