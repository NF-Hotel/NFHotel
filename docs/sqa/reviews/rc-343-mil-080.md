## Findings

- **The plan matches the repository at f83859e.** Every compose file under `ops/deploy` drops all capabilities and sets `no-new-privileges`, a read-only root and limits; `ops/scripts/cis-evidence.sh` prints the settings without comparing them; `git grep check-e2e-stack` finds the script and `ops/tests/lib/hardening.sh` only, no caller; the action `e2e-tests` starts the stack and runs the end-to-end tests and the log privacy check, not the hardening check. The commit f824b5b of NF-Hotel/DevOps had the job "End-to-end stack" that ran it.
- **The deploy gate cannot block a rollback by itself.** It checks only the containers of the services with a profile and prints an unknown container as a warning, and a release from before MIL-080 has no check, so a rollback to it runs none.
- **The kernel's view is the point of "actually".** The settings of `docker inspect` say what Docker was asked; `/proc/<pid>/status` and the AppArmor label say what the main process holds. Both are read.
- **What is left depends on S01.** The deploy of the monitoring runs over Tailscale SSH in check mode, which S01 confirms in the browser; if that confirmation does not come, criterion 5 waits, and the gate says so.

## Overall Verdict

Go. Every Mandatory criterion of QC-MIL-001 and QC-LANG-001 passes. MIL-080 is Accepted as the AI's stand-in decision for S01 in autonomous mode; it stays open to S01's challenge in the summary of the run.
