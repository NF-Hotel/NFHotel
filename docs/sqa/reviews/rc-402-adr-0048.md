## Findings

- **F1, for S01: two points of the brief are recommendations of the RFC, not requirements.** The brief listed a
  redirect of the live file, and a Canonical that does not name the address the file was fetched from, among the
  requirements of RFC 9116. Section 3 allows a redirect ("may result in a redirect"), and section 2.5.2 says only that
  such a file SHOULD NOT be trusted. The ADR keeps both as failures of the check, but as rules of this project, so a
  message never claims a requirement that the RFC does not make. The same goes for `Bug-Bounty` twice: the registry
  of IANA marks it as a field that appears once, and RFC 9116 does not name it.
- **F2, corrected while writing: three sentences said more than was checked.**
    - The value that the HTTPS server of the tailnet sends is in `nginx.env` on the virtual machine, not in git. The
      ADR now says what the wiki page Environment-Files sets (a year with a real certificate), not what the server
      sends.
    - The proxy runs an image of its own (`ops/deploy/nginx/Dockerfile`). The ADR now says that the image copies in
      no configuration, which the comment and the content of the `Dockerfile` show.
    - Option 1 said that the static web assets take `wwwroot\**` "without" the dot folders; the props file includes
      `wwwroot\**` with `$(DefaultExcludesInProjectFolder)` as its exclude, and the ADR now says so, with the lines.
- **F3, corrected while writing: abbreviations.** URI, CI and TLS were used without their long form; each is now
  spelled out at its first use.
- **F4, note: the exceptions, accepted by the AI as stand-in for S01.** E1 (no signature), E2 (no role address), E3
  (no key for encryption) and E4 (no safe-harbour promise) each say why and what reopens it. S01 named neither a role
  address nor a key on 2026-11-18 and left the wording of the policy to the AI on 2026-11-17, so the stand-in
  acceptance follows S01's own answers; S01 may still challenge it in the summary of the run. Accepting the ADR
  accepts them; the check shows each as an expected warning, so closing one later fails the check until the ADR and
  the option `--expect-warnings` change together.
- **F5, note: what is not claimed.** The ADR claims conformance with RFC 9116 and sections 3 and 4 of RFC 8615 only.
  ISO/IEC 29147 and ISO/IEC 30111 were not read; RFC 3339, RFC 5646, RFC 5198, RFC 2142 and RFC 4880 were used
  through RFC 9116, not read themselves.
- **F6, note: a date that closes the gate.** From 30 days before the Expires, the job `Ops nginx routes` fails on
  every pull request and every push to `main`, so CD stops until the date moves. The ADR lists this as its first
  negative consequence; the wiki pages of task 6 say it too.

## Overall Verdict

[MIL-084] to autonomous mode in chat; the summary of the run names the acceptance, and S01 may challenge it there.
