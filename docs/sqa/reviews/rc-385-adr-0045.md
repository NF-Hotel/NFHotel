## Findings

- **F1, fixed in the review: the generic API tool.** The draft left the logs out with `--disable-loki` alone. The
  README of v2.1.1 lists `grafana_api_request`, which calls any API of Grafana and reaches Loki through the proxy of
  the data source; the README calls it a full bypass of a limit on Loki. `run_panel_query` and `get_panel_image`
  would show the panel of logs of the overview dashboard (panel 6, on the Loki data source). Decision 5 now names an
  allowlist, `--enabled-tools=prometheus,alerting,dashboard,search`, so only those groups are registered, and a group
  that a later release adds stays off; the entry of the wiki carries the same flags.
- **F2, fixed in the review: two more flags.** `--disable-write` registers no tool that writes, on top of the Viewer
  role. The server sends a usage report to Grafana Labs every 4 hours by default; it holds no query and no log line,
  but `--usage-stats=disabled` stops it.
- **F3, fixed in the review.** Option 5, the service account in an organization of its own, is among the options,
  the quality attributes have a paragraph, and the abbreviations of criterion 10 are spelled out.
- **F4, a stand-in decision open to S01: the logs are out.** The check found personal data of visitors (the IP
  address and the user agent of each request in the log of nginx) and of staff (the Tailscale login and the command
  line of each SSH session in the journal), and none of guests in a value: the API hides every parameter of its SQL.
  Criterion 2 of [MIL-052] then leaves the logs out, or removes the data at the source first. Removing it at the
  source (the address and the user agent in Alloy, the journal of `tailscaled`) would change the monitoring and take
  from the logs what an incident needs most; it is not part of [MIL-052].
- **F5, a stand-in decision open to S01: the release and the expiry.** v2.1.1 (2026-10-20) is the newest release at
  least 14 days old on 2026-11-15; v2.2.0 (2026-11-02) and v2.3.0 (2026-11-10) are younger. The token lives 30 days:
  long enough to use it for the rest of the plan with one renewal, short enough that a token left behind expires.
- **F6, note: the limit on the logs rests on the MCP server.** In the open-source edition of Grafana a Viewer can
  query every data source, as the ADR says. Within the server, the Prometheus tools take any data source and query
  it through the resource route of its plugin, with the proxy of the data source as their fallback. On 2026-11-15
  Loki answered `404` to `/api/v1/query`, `/api/v1/labels` and `/prometheus/api/v1/query` (with `vector(1)`, from the
  LXC), so the fallback returns no log line; task 5 shows through the server that a Prometheus query against the
  Loki data source returns none either.
- **F7, note for task 5: the refused writes.** With `--disable-write` no write tool is registered, so the four writes
  of criterion 3 cannot be sent through the entry of the wiki. They can be sent through a second entry that S01 adds
  for the test only, with the same token and without `--disable-write`, and removes after it; Grafana must answer
  each with `403`. A request with `curl` would put the token on a command line, which decision 4 rules out.
- **F8, note: "the assistant never sees the token" is a rule, not a wall.** The assistant runs on S01's PC as S01,
  so its tools could read `~/.claude.json`. It keeps the rule, and criterion 5 checks the places where the token
  could appear (the repository, the commits and the chat); option 5 would also keep a token that did leak away from
  the logs.

## Overall Verdict

Go. Every Mandatory criterion of [QC-ADR-001] passes after the fixes of F1 to F3. ADR-0045 is Accepted as the AI's
stand-in decision for S01 in autonomous mode, under the plan that S01 accepted in chat on 2026-11-14 and S01's request
of 2026-11-15; F4, F5 and F8 stay open to S01's challenge. With it, criteria 1 and 2 of [MIL-052] are met; the gate
checks them with the others.
