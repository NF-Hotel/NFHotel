## Findings

- **Findings 2 and 3 came from the code, not from the scans.** The scans do not sign in, so they do not reach the benchmark page, and they did not post the login form with an empty user name. Tasks 2 and 4 reproduce each finding before the change, so the fix rests on a test, not on the reading; task 4 keeps its test as a regression test if the finding does not reproduce, and its review record says so.
- **The fix is in the parameters, not in a rule.** No ZAP rule is added: the alert (30003) is fixed, and criterion 6 proves it with a full scan after the deploy. Task 3 makes a new page with a typed query parameter fail a test, so the error cannot come back unnoticed.
- **The plan matches the code of `main` at b1abd8e.** `Book.razor.cs` binds `guests` as `int?`, and `checkIn` and `checkOut` as `string?`; `BookingFlowViewModel.Prefill(string? checkIn, string? checkOut, int? guests)` keeps the number between 1 and `MaxGuests` (4); `BenchmarkStart.razor.cs` binds `again` as `Guid?` behind `StaffPolicies.BenchmarkRun`; `Login.razor.cs` clears `Input.Password` only in `SignInAsync`, which `OnValidSubmit` runs; `WebFactory` is in `NFHotel.Web.Tests`. The one other query parameter of the web application, `returnUrl` of the login page, is a string already.
- **Abbreviations and a bracket were changed before this record.** CD and GUID are spelled out, the sentence with HTML and HTTPS was rewritten, and "Integer Overflow Error [30003]" now reads "(30003)", so the brackets cannot be taken for a link label (criterion 10).
- **One CD run at a time.** The CD run of the merge of MIL-066 (42489880568) still waits for S01; the CD run of MIL-067 comes after it (ADR-0038).
- **The acceptance covers the language and the terms.** As for MIL-066 ([RC-306]), criteria 3, 5 and 9 rest on the acceptance of S01, who can challenge them in the summary of the run.
